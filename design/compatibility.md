# Upstream compatibility and certification contract

This inventory reads the current exports in [src/index.ts](../src/index.ts), the current [README](../README.md), [current Docusaurus docs](../docs/docs), and implementations at e03e3edbeadc68512d3d0c935ea02a3c6a93cfee. The frozen functionality baseline is 30cf1f86a590a1d8bb183a36b1887fa30e908d4e. Archived `docs/versioned_docs/version-7.x` describes an older renderer API (Stage, withFilters, custom component factories); it is retained documentation, not an additional wave-1 API promise. The [architecture](adapter-architecture.md) resolves boundaries and failure semantics. No runtime behavior changes in this design PR.

Ticket links: [core/factory 7](https://github.com/baseten/pixi-react/issues/7), [Pixi 8](https://github.com/baseten/pixi-react/issues/8), [React 19](https://github.com/baseten/pixi-react/issues/9), [facade 10](https://github.com/baseten/pixi-react/issues/10), [types 11](https://github.com/baseten/pixi-react/issues/11), [React18 12](https://github.com/baseten/pixi-react/issues/12), [conformance 6](https://github.com/baseten/pixi-react/issues/6), [matrix 13](https://github.com/baseten/pixi-react/issues/13). Numbers below refer to these exact tickets. Every preserve/correct row requires a named conformance scenario in 6 and its owning package's fixture; corrections are explicit compatibility decisions, not accidental consequences of extraction.

## Certification policy

The [audit seed](compatibility/seed.json) and [evidence](compatibility/evidence.json) are immutable inputs to this design, not proof of a production adapter. All epoch rows are currently `candidate-not-certified`. A package's initial supported range is the union of successfully certified **exact tuples**, later widened only after the matrix covers its advertised interval/features. Peer ranges must be no broader than that certificate; a bounded candidate range is a test plan, not the initial peer declaration.

| Candidate React interval | Exact reconciler / bridge | Test endpoints from audit | Pixi target |
| --- | --- | --- | --- |
| `>=19.0.0 <19.1.0` | 0.31.0 / 2.1.1 | 19.0.0, 19.0.8 | Certified subset of Pixi8 candidates |
| `>=19.1.0 <19.2.0` | 0.32.0 / 2.1.1 | 19.1.0, 19.1.9 | Same independently verified scene |
| `>=19.2.0 <19.3.0` | 0.33.0 / 2.1.1 | 19.2.0, 19.2.8 | Activity visibility/effects included |
| `>=19.3.0 <19.4.0` | 0.34.0 / 2.1.1 | 19.3.0 | Fragment-ref policy and explicit ViewTransition rejection included |
| `18.3.1` | 0.29.2 / 1.2.5 | 18.3.1 | Same Pixi8, issue 12 after modern parity |

Pixi8 candidate envelope is `>=8.2.6 <8.23.0` at this audit, with evidence sampled through 8.22.0. This does not certify unprobed patches. Preserve the exact 8.2.6 floor; implement capability boundaries at particles 8.5, cacheAsTexture 8.6, RenderLayer 8.7, DOMContainer 8.9, Canvas 8.16, visibleChanged 8.17 and contextmenu 8.22. Canvas is excluded until separately validated; WebGL/WebGPU are individually certified, never inferred from each other. Pixi8.5.0 particle destruction is an explicit failing feature cell; exclude that node capability there until a proven workaround, without declaring all ordinary 8.5.0 nodes broken. The sampled later passing patch is 8.5.2, not a discovered first fixed patch. Pixi7.4.2/7.4.3 are reserved wave-2 candidates. No React <=17, earlier Pixi7 or Pixi <=6 support is introduced.

A matrix certificate records exact React/reconciler/bridge/types/Pixi/compiler/node/browser/backend versions, resolved integrities, ESM/CJS and JSX mode, advertised capability IDs, and results from packed installed consumers plus real renderer scenarios. Issue 13 owns the machine-readable output and missing-cell failure; 6 defines scenarios; 8/9/11/12 bind them. Unit mock success or the audit's minimal host does not turn a cell green. Promotion requires the audit's registry/tag review, isolated integrity-recorded install, consumer/host probes, real browser lifecycle, async cancellation/recovery, contexts/effects, props/events/constructors, special nodes, shared resources/globals and advertised feature paths. Future patches/minors stay outside the certificate until explicitly promoted; owner review is required to remove promised support.

## Limits and follow-through

The design consumer sketches test the neutral inference mechanism and representative installed React/Pixi signatures, not packed future packages, complete catalogs or browser implementation. Issue 11 must replace representative mappings with the full audited constructor/event/readonly/child policy and prove classic, automatic and dev JSX under separate React19/18 installations. NodeNext and bundler consumers must use package exports, not tsconfig aliases. The default facade may augment global tags; adapter/factory imports may not. Conflicting tag declarations cannot coexist in one TypeScript program: local typed components or separate programs are required.

The React19 ticket's four concrete workspaces and per-epoch feature obligations are in the architecture's epoch plan. Keeping them in one PR is a scope judgment; widening into DOM ViewTransition animation support is not authorized. Namespace ownership remains the only publication decision left to the owner; runtime unsupported capabilities fail before use. Third-party SDK packaging and Pixi7 belong to the explicitly excluded future wave. These limits do not leave any acceptance criterion of this design ticket stubbed: they define the implementation boundaries and the evidence downstream tickets must supply.
