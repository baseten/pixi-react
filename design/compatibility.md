# Upstream compatibility and certification contract

This inventory reads the current exports in [src/index.ts](../src/index.ts), the current [README](../README.md), [current Docusaurus docs](../docs/docs), and implementations at e03e3edbeadc68512d3d0c935ea02a3c6a93cfee. The frozen functionality baseline is 30cf1f86a590a1d8bb183a36b1887fa30e908d4e. Archived `docs/versioned_docs/version-7.x` describes an older renderer API (Stage, withFilters, custom component factories); it is retained documentation, not an additional wave-1 API promise. The [architecture](adapter-architecture.md) resolves boundaries and failure semantics. No runtime behavior changes in this design PR.

Ticket links: [core/factory 7](https://github.com/baseten/pixi-react/issues/7), [Pixi 8](https://github.com/baseten/pixi-react/issues/8), [React 19](https://github.com/baseten/pixi-react/issues/9), [facade 10](https://github.com/baseten/pixi-react/issues/10), [types 11](https://github.com/baseten/pixi-react/issues/11), [React18 12](https://github.com/baseten/pixi-react/issues/12), [conformance 6](https://github.com/baseten/pixi-react/issues/6), [matrix 13](https://github.com/baseten/pixi-react/issues/13). Numbers below refer to these exact tickets. Every preserve/correct row requires a named conformance scenario in 6 and its owning package's fixture; corrections are explicit compatibility decisions, not accidental consequences of extraction.

## Owner decisions applied here

The owner decisions are recorded in the [architecture](adapter-architecture.md#owner-decisions-d1d6). This inventory applies them as follows:

- **D1.** The default facade imports the newest certified React 19 epoch. Consumers on an older certified epoch pin it through `createRenderer`, not through the facade. Amended for the facade by [issue 49](https://github.com/baseten/pixi-react/issues/49) (2026-10-09): its React peer is `^19.3.0` instead of the certified minor only, and another React 19 minor logs one runtime warning naming the tested version (19.3.0) and how to pin. Release 1 calls its versions tested, not certified, until a range is promoted ([release.md](release.md#what-tested-means), issue 40).
- **D2 (reversed 2026-10-09, [issue 49](https://github.com/baseten/pixi-react/issues/49)).** Was: one `react-19` package with `exports` subpaths `/19.0`–`/19.3`, each bundling its exact reconciler. Now each React minor is its own package (`react-19.0` … `react-19.3`, and `react-18`), with its exact `react-reconciler` and its-fine as ordinary dependencies and an exact React peer; see the [architecture](adapter-architecture.md#one-package-per-react-minor-d2-reversed).
- **D3.** `createRenderer` takes `{ react, pixi }` (reversed on 2026-10-09 from the neutral `{ framework, scene }`; [issue 44](https://github.com/baseten/pixi-react/issues/44)).
- **D4.** Strict upstream parity in the facade. Rows below carry one of these labels where D4 changes the outcome:
  - *Preserve now / correct in future major*: the correction changes behaviour or types that upstream programs can observe on a working path (a new error, a narrower type, a different value). The facade keeps upstream behaviour until a documented future major. The modular packages may ship the corrected behaviour earlier only where the facade can still select the upstream behaviour when it composes them (for example a registry conflict policy that the facade sets); the owning issue decides this and tests both behaviours.
  - *Modular packages only*: a new API (`useContextBridge`, `component(Ctor)`, root error props on `Application`, `Root.status`, public `unmount`). The facade does not export it.
  - *Failure-path repair, pending owner decision*: the change affects only paths where upstream hangs, leaks, double-initialises or leaves an unhandled rejection. **Ruled (issue 1 progress update, 2026-10-09): approved.** The default facade inherits the adapters' repairs of crash, leak, hang and unhandled-rejection paths; its public API and documented behaviour stay exactly as upstream. Rows still carrying this label are now repaired in the facade (issue 10).
  - Rows without a label are parity, or the correction is documentation-only.

  The *preserve now / correct in future major* rows are the change list for that future major.
- **D5.** Peer ranges cover exactly-certified versions only (see the certification policy).
- **D6.** ESM and CJS entries share one canonical runtime instance; #5/#7 choose the mechanism.

### Facade parity shims (issue 10)

The default facade (`packages/react`) composes `React19Adapter` (`react-19.3`) and `Pixi8Adapter` with `registryConflict: 'replace'`. Where upstream behaviour differs from an adapter's, the facade keeps upstream's with a shim of its own; no adapter default changes, so a `createRenderer` composition of the same pair gets the modular behaviour.

| Shim (in `packages/react/src`) | Upstream behaviour kept |
| --- | --- |
| `components/Application.tsx` `GlobalSettings` | `extensions` added to Pixi's registry before init and never removed on unmount (the swap defect repaired); `defaultTextStyle` merged globally, the load-time default merged back when absent, nothing restored on unmount. The adapter's leases and style writer are never used by the facade. |
| `runtime/applicationOptions.ts` | Every application option copied onto the Pixi `Application` after init on each render (read-only members skipped). |
| `runtime/pixiAdapter.ts` | Event props passed to constructors under both names; constructors Pixi8Adapter does not support registered by `extend` and dropped silently (constructed, never attached, `destroy()` on removal). |
| `helpers/extend.ts` | `extend` never throws for a catalog entry. |
| `core/createRoot.ts` | Upstream `Root` shape (`applicationState` with destroy options, `fiber` key, `internalState`); a repeated `createRoot` returns the known root silently; `resizeTo` kept when a later `render` omits it; `extensions`/`defaultTextStyle` never reach the scene globals. |
| `hooks/useApplication.ts`, `hooks/useTick.ts` | Upstream's "No Context found" error outside an application; `useTick`'s callback check. Inside another runtime's application the adapter's `react-19.FOREIGN_RUNTIME` error is kept. |
| `runtime/applyProps.ts` | The deprecated diff-set form of `applyProps`. |

## Certification policy

The [audit seed](compatibility/seed.json) and [evidence](compatibility/evidence.json) are immutable inputs to this design, not proof of a production adapter. All epoch rows are currently `candidate-not-certified`. A package's initial supported range is the union of successfully certified **exact tuples**, later widened only after the matrix covers its advertised interval/features. Peer ranges must be no broader than that certificate (D5): they list exactly-certified versions, never an untested interval. A bounded candidate range is a test plan, not the initial peer declaration. The facade's React peer is the exception (D1 as amended by issue 49): `^19.3.0`, tested with 19.3.0 only, with a runtime warning on any other React 19 minor, so that installs never fail with ERESOLVE. Since D2 was reversed (issue 49), each React minor is its own package, so each package's React peer range is exactly its own certified versions (`react-19.0`: `19.0.0 || 19.0.8`; `react-19.1`: `19.1.0 || 19.1.9`; `react-19.2`: `19.2.0 || 19.2.8`; `react-19.3`: `19.3.0`; `react-18`: `18.3.1`), and each package rejects an installed React of another minor at composition time (an explicit adapter assertion, never adapter selection).

| Candidate React interval | Package; exact reconciler / bridge (dependencies) | Test endpoints from audit | Pixi target |
| --- | --- | --- | --- |
| `>=19.0.0 <19.1.0` | `react-19.0`; 0.31.0 / 2.1.1 | 19.0.0, 19.0.8 | Certified subset of Pixi8 candidates |
| `>=19.1.0 <19.2.0` | `react-19.1`; 0.32.0 / 2.1.1 | 19.1.0, 19.1.9 | Same independently verified scene |
| `>=19.2.0 <19.3.0` | `react-19.2`; 0.33.0 / 2.1.1 | 19.2.0, 19.2.8 | Activity visibility/effects included |
| `>=19.3.0 <19.4.0` | `react-19.3`; 0.34.0 / 2.1.1 | 19.3.0 | Fragment-ref policy and explicit ViewTransition rejection included |
| `18.3.1` | `react-18`; 0.29.2 / 1.2.5 | 18.3.1 (18.2.0 evaluated in issue 12, not certified: 0.29.2 declares `react@^18.3.1`) | Same, unchanged Pixi8Adapter; fixture cells 8.2.6 and 8.22.0 ([packages/react-18](../packages/react-18/README.md)) |

Pixi8 candidate envelope is `>=8.2.6 <8.23.0` at this audit, with evidence sampled through 8.22.0. This does not certify unprobed patches. Preserve the exact 8.2.6 floor; implement capability boundaries at particles 8.5, cacheAsTexture 8.6, RenderLayer 8.7, DOMContainer 8.9, Canvas 8.16, visibleChanged 8.17 and contextmenu 8.22. Canvas is excluded until separately validated; WebGL/WebGPU are individually certified, never inferred from each other. Pixi8.5.0 particle destruction is an explicit failing feature cell; exclude that node capability there until a proven workaround, without declaring all ordinary 8.5.0 nodes broken. The sampled later passing patch is 8.5.2, not a discovered first fixed patch. Pixi7.4.2/7.4.3 are reserved wave-2 candidates. No React <=17, earlier Pixi7 or Pixi <=6 support is introduced.

A matrix certificate records exact React/reconciler/bridge/types/Pixi/compiler/node/browser/backend versions, resolved integrities, ESM/CJS and JSX mode, advertised capability IDs, and results from packed installed consumers plus real renderer scenarios. Issue 13 owns the machine-readable output and missing-cell failure; 6 defines scenarios; 8/9/11/12 bind them. Unit mock success or the audit's minimal host does not turn a cell green. Promotion requires the audit's registry/tag review, isolated integrity-recorded install, consumer/host probes, real browser lifecycle, async cancellation/recovery, contexts/effects, props/events/constructors, special nodes, shared resources/globals and advertised feature paths. Future patches/minors stay outside the certificate until explicitly promoted; owner review is required to remove promised support.

## Limits and follow-through

The design consumer sketches test the neutral inference mechanism and representative installed React/Pixi signatures, not packed future packages, complete catalogs or browser implementation. Issue 11 must replace representative mappings with the full audited constructor/event/readonly/child policy and prove classic, automatic and dev JSX under separate React19/18 installations. NodeNext and bundler consumers must use package exports, not tsconfig aliases. The default facade may augment global tags; adapter/factory imports may not. Conflicting tag declarations cannot coexist in one TypeScript program: local typed components or separate programs are required.

The React19 ticket's per-epoch feature obligations are in the architecture's epoch plan; its single `react-19` package with four subpaths (D2) became four per-minor packages in issue 49. Keeping them in one PR is a scope judgment; widening into DOM ViewTransition animation support is not authorized. Namespace ownership remains the only publication decision left to the owner; runtime unsupported capabilities fail before use. Third-party SDK packaging and Pixi7 belong to the explicitly excluded future wave. These limits do not leave any acceptance criterion of this design ticket stubbed: they define the implementation boundaries and the evidence downstream tickets must supply.
